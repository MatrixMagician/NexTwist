# Quick Task 260802-a01 — Summary

Codebase-architecture cleanup: restored the "no logic in adapters" boundary in two places
where it had leaked, gave the frontend the same pure-module seam the engine already has,
and closed the gap where the documented frontend gates were never actually run by CI.

## Problems found

1. **`frontend/src/routes/+page.svelte` was a binary blob to git.** Two stray NUL bytes in
   one comment (`"step\0group\0option"`) made git classify the 2647-line UI file as binary,
   so every diff and code review of the frontend rendered as `Bin 103470 -> 103470 bytes`.
2. **No frontend seam.** The FOMOD wizard selection rules (group-type radio/checkbox
   semantics, min/max step validity, flag accumulation), the masters-first plugin reorder
   rule, and the byte/percent formatters all lived inline in the route, so none of them
   could be tested without a webview — the mirror image of the boundary the Rust engine
   deliberately maintains.
3. **Engine logic in a Tauri adapter.** `merged_plugins_locked` hand-rolled the D-07/D-13
   merge (stored enable/order onto the scan, protected stamping, display sort) inside
   `src-tauri`, which AGENTS.md explicitly reserves for thin delegation.
4. **Duplicated safety-adjacent helper.** `downloads.rs` and `fomod.rs` each carried a
   byte-identical `sanitize()` differing only in its fallback string, and only one of the
   two copies had any test — exactly the drift the engine boundary exists to prevent.
5. **Ungated gates.** The definition of done listed `npm run check`, and no CI step ran it;
   there were no frontend tests at all.

## Changes

- **`fix(frontend)` `1ebd2be`** — removed the NUL bytes and reworded the comment. The UI
  file now diffs as text.
- **`refactor(frontend)` `6fd6f20`** — new pure `$lib` modules `fomod.ts`, `plugins.ts`,
  `format.ts`, wired into the route; 25 vitest cases including a property-style check that
  no legal `reorder` can put a regular plugin before a master; vitest added and both
  `svelte-check` and the tests gated in `ci.yml`.
- **`refactor(loadorder)` `63423f8`** — `merge_plugin_state` + `enabled_names` moved into
  the engine as pure functions with 6 tests (scan-owns-kind, unstored defaults, protected
  cleared on a degraded probe, idempotency). The adapter now only gathers inputs.
- **`refactor(extract)` `e79424c`** — `extract::staging_dir_name(name, fallback)` replaces
  both `sanitize()` copies, with a property test asserting the result is always exactly one
  `Component::Normal` (traversal, absolute paths, NUL, newlines, emoji).
- **`docs` `37b9d0a` / `9adef76`** — AGENTS.md records the frontend `$lib` boundary and the
  vitest gate; CHANGELOG.md `[Unreleased]` records the batch.

## Deliberately not done

The residual adapter code (`premium_gate`, `build_client`, `replay_for`,
`persist_collection_mod`, `project_module`) is genuinely adapter-shaped work — keyring and
`AppState` access, DTO projection for serde, and orchestration of engine calls. Pushing it
into `crates/*` would drag Tauri/keyring concerns across the boundary it is meant to
protect, so it was left alone.
