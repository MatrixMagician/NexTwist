<objective>
Expose Plan-01's INI-activation engine to the user: a thin Tauri adapter (`preview_ini_activation` + `apply_ini_activation` with a conflict-resolution choice) and a Starfield-only frontend surface (activation state, no-silent-edit preview modal, conflict box) assembled entirely from existing `+page.svelte` classes per the 08-UI-SPEC design contract.

This delivers the user-facing half of SFINI-01 (no silent edit — the exact reversible change is shown and confirmed before writing) and SFINI-03 (a non-empty user `sResourceDataDirsFinal` surfaces as a blocking conflict with an explicit keep-mine / use-NexTwist choice, never a silent clobber). The engine remains the sole owner of safety logic; the adapter is 3-5 lines per command and the UI reuses the exact Phase-6/7 notice + FOMOD/profile-switch dry-run modal patterns.

Purpose: Give the user an explicit, previewable, reversible path to enable loose-file loading and to resolve an INI conflict — matching the v1.0 dry-run discipline.
Output: `src-tauri/src/commands/gameconfig.rs` (thin adapter) + registration, `api.ts` bindings + TS types, and the three Starfield-view surfaces in `+page.svelte`.
</objective>
