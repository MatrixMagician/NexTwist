<objective>
Build the headless, std-only INI-activation engine module `crates/deploy/src/gameconfig.rs` plus its journal + error seams. This is the safety-critical core of Phase 8: a surgical byte-fidelity INI editor and a set of journaled op wrappers (`ensure_ini_active`, `restore_ini`, `preview_ini_activation`) that reuse the existing content-addressed vanilla backup + operation journal VERBATIM, changing only WHERE the target resolves (the Proton-prefix `My Games/Starfield/StarfieldCustom.ini`, never `Data/`).

This is the first sanctioned engine write OUTSIDE the `Data/` deploy root. The reversibility substrate (backup, journal, empty-dir pruning) already exists and is battle-tested; this plan wires a new ~120-LOC module into it with a distinct `KIND_INI` journal token and an independent `steam::my_games_path` resolution, leaving the `Data/`-root guard completely untouched.

Purpose: Deliver reversible, byte-for-byte, journaled loose-file activation for Starfield (SFINI-01/02/03/04) at the engine layer, so the choke-point wiring (Plan 02) and the UI (Plan 03) become thin callers.
Output: `gameconfig.rs` (surgical editor + op wrappers), a `KIND_INI` journal arm, a typed `DeployError::IniConflict`, and unit tests proving byte fidelity, provenance restore, idempotency, and conflict blocking. Adds ZERO external crates.
</objective>
