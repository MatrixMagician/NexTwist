<objective>
Wire the Plan-01 INI engine into the existing deploy/purge/recovery choke points, gated on Starfield, and prove the full reversibility guarantee end-to-end with an integration suite modelled on `vanilla_restore.rs` / `crash_recovery.rs`.

This is where SFINI-04 idempotency (deploy×2 / profile-switch / crash-replay → one `[Archive]`, identical bytes) and SFINI-05 (crash recovery via `recover_on_launch` + verify/repair participation + the testkit reversibility suite across both provenance branches) become observable behaviours. The wiring is a handful of `is_starfield`-gated tail calls plus one `is_starfield`-gated INI-drift check in `verify`/`repair`; the substance is the regression-locking test suite.

Purpose: Make loose-file activation ride the SAME reversibility lifecycle as file deployment — automatic ensure on deploy, provenance restore on purge, idempotent crash replay, and verify/repair drift detection + re-activation — and lock it against regression.
Output: `is_starfield`-gated hooks at the tails of `deploy`/`deploy_winners`/`purge`, an `is_starfield`-gated INI-drift arm in `verify`/`repair`, and `crates/deploy/tests/ini_activation.rs` — the reversibility suite covering both provenance branches, idempotency, conflict, CRLF/BOM, the KIND_INI-path-under-prefix guard, and verify-detects-drift / repair-restores.
</objective>
