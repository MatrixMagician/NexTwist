<objective>
Wire the 07-01 engine additions through the thin Tauri command layer so the frontend (07-03)
can render them. NO safety/format/classification logic lives here — these adapters gather the
store reads (managed game, active profile, enabled mods, plugin state) and forward exactly one
headless `loadorder` call, mapping the typed `LoadOrderError` to a `String` at the IPC boundary
(the established `crates/*` headless / thin-adapter boundary).

Two changes:
1. `list_plugins` returns the richer `PluginView` (medium + protected) instead of bare
   `core::Plugin`: medium comes from `scan_plugin_views_for`; protected comes from the live
   `loadorder::protected_plugins` probe (SFLO-03).
2. A new thin `reconcile_plugins` command surfaces the SFLO-04 `ReconcileState`: it reads the
   active profile's recorded `plugin_state`, reads the on-disk `plugins.txt` from the prefix
   AppData, computes the protected set, and calls `loadorder::reconcile_plugins_txt` (SFLO-04).

`save_plugin_order` and `sort_with_loot` need no logic change — the enriched wire object still
deserializes into `core::Plugin` (serde ignores the extra `medium`/`protected` fields), and
`SortProposal` simply gained a `masterlist_date` field the frontend reads.

Purpose: expose engine truth to the UI without moving any authority out of the engine.
Output: an enriched `list_plugins`, a new `reconcile_plugins` command, and its registration.
</objective>
