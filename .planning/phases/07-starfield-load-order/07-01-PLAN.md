<objective>
Extend the shipped v1.0 headless load-order engine (`crates/loadorder` + `crates/testkit`)
with the three CE2-specific additions Phase 7 needs — all reads of an existing
libloot/esplugin signal plus a classification, with ZERO `core` change, ZERO DB migration,
ZERO dependency/MSRV bump:

1. **Medium-master classification** (SFLO-03): a `medium: bool` derived from
   `esplugin::Plugin::is_medium_plugin()`, carried on a NEW `PluginView` wire model
   (NOT `core::Plugin`, which is frozen).
2. **Protected/implicitly-active determination + defensive engine guard** (SFLO-03):
   `protected_plugins()` via `libloot::Game::is_plugin_active()` (never a hard-coded name
   list), plus a typed rejection in `apply_load_order` of any reorder/disable of a
   protected master.
3. **SFLO-04 reconciliation**: a pure `reconcile_plugins_txt()` returning a classified
   `ReconcileState { InSync | Drift(names) }`, treating the game's known on-launch rewrite
   as expected rather than drift.

Plus the small supporting bits: a masterlist-snapshot-date source (SFLO-02 age note), a new
`LoadOrderError::ProtectedMaster` variant, and the testkit medium-flag fixture. The
asterisk-write (`apply_load_order`), LOOT sort (`propose_sort`), and masterlist
(`ensure_masterlist`) paths are REUSED VERBATIM — this plan only adds tests that exercise
them for Starfield and two derived booleans + one reconcile fn.

Purpose: this is the engine authority layer. The Tauri wiring (07-02) and the frontend
surfacing (07-03) render exactly what this layer computes; the safety guarantee (protected
masters cannot be reordered/disabled) lives HERE, not in the UI.
Output: new + extended symbols in `crates/loadorder` and `crates/testkit`, fully unit/
integration-tested headless (no WebKitGTK).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin files on disk → esplugin header parse | untrusted mod/game plugin bytes are header-parsed (names treated as opaque filenames) |
| desired plugin order (from the store/UI) → `apply_load_order` | a caller-supplied order could try to move/disable a protected base master |
| on-disk `plugins.txt` (game-rewritten, in prefix AppData) → `reconcile_plugins_txt` | untrusted text lines compared against recorded state, read-only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Tampering | `apply_load_order` protected-master handling | high | mitigate | Defensive engine guard returns typed `LoadOrderError::ProtectedMaster` on any disable/reorder of a protected master — enforced in the engine, not only the UI (SFLO-03, Task 2). |
| T-07-02 | Tampering | plugin filename in `plugins.txt` / scan | low | mitigate | Names treated as opaque strings; never joined as a path outside `Data/`; esplugin header-parses each (existing scan.rs T-02-12 behavior, unchanged). |
| T-07-03 | Tampering | asterisk `plugins.txt` write location | medium | mitigate | Write goes ONLY through the existing libloot `active_plugins_file_path` seam bounded under the resolved prefix AppData (asserted by the `starfield_asterisk` bounds test); no new write path introduced. |
| T-07-04 | Information Disclosure | `reconcile_plugins_txt` | low | accept | Read-only string classification; no secrets, no network, no disk mutation. |
| T-07-SC | Tampering | cargo installs | low | accept | No new package: `libloot 0.29.5` / `esplugin 6.1.4` are already vendored + legitimacy-approved at Phase 2; `deny.toml` unchanged (07-RESEARCH § Package Legitimacy Audit = N/A). |

No `high` threat is left unmitigated (T-07-01 is mitigated by the engine guard).
